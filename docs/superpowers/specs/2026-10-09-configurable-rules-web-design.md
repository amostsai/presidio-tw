# 設定檔規則、原格式脫敏與復原 Web 介面

## 需求與現況

使用者希望將身分證、姓名、手機等辨識設定移出程式，讓後續可透過設定檔擴充比對規則，並透過 Web 上傳 DOCX、XLSX、PDF、TXT、CSV、JSON、XML。

使用者進一步指定：脫敏結果必須以來源格式下載，排版盡量一致，同時提供獨立還原檔。另提供復原功能，可上傳 AI 回覆檔案或貼上文字，再上傳還原檔，將代碼換回真正的姓名、身分證等內容。這取代前一版僅輸出 TXT 的假設。

目前專案只有 app.py，使用 Presidio 的正則 Recognizer、台灣證號校驗函式，以及 CKIP NER 模型；直接執行時會分析示範文字並輸出脫敏結果。現有 app.py 已在 Git 暫存區，尚無任何提交。

## 建議方案與替代方案

採用 YAML 規則檔、獨立辨識服務及 FastAPI 搭配伺服器模板的 Web 介面。延續現有 Python 程式，避免額外引入前端建置流程，也能共用命令列與 Web 的辨識邏輯。

替代方案為 Streamlit，可更快完成展示，但自訂上傳及下載介面的彈性較低；另一方案是獨立前端與 API，適合更大規模產品，但目前需要額外維護兩套應用。此階段選擇 FastAPI。

## 規則設定

- 預設使用 config/rules.yaml，可透過命令列或環境變數指定其他路徑。
- 每條規則包含名稱、啟用狀態、entity、patterns（名稱、regex、score）、context、可選 validator，以及代碼類型。可復原模式統一使用唯一代碼，不能使用會遺失對應關係的固定遮罩。
- 將身分證、統編、手機的正則與上下文移至 YAML，保留原有校驗函式；validator 使用固定名稱對應函式，設定檔不執行任意 Python。
- CKIP 的啟用狀態、模型名稱、device、分數、標籤對應與處理片段長度均由設定檔指定，預設維持姓名、組織、地點辨識。姓名仍由模型辨識；也可新增姓名詞庫或正則規則。
- 新增正則或固定詞庫規則只需修改設定檔。新增全新的校驗演算法則需要實作並註冊函式。
- 啟動時驗證設定結構、正則及分數；錯誤訊息指出問題規則。修改設定後重新啟動服務生效，此階段不提供瀏覽器編輯規則。

## 可復原代碼與還原檔

- 每次脫敏工作產生隨機工作識別碼；代碼採 ASCII，如 `[[PERSON_a4c83e21_0001]]`。同一工作內相同類型與相同原文共用代碼，不同原文使用不同代碼。
- 原文已包含類似代碼時檢查碰撞，重新產生識別碼，不能誤認為此次產生的代碼。
- 獨立還原檔採 UTF-8 JSON，包含版本、工作識別碼、原始檔名、代碼、entity 與原文。還原檔本身包含完整個資，介面清楚提示保存在本機，傳給 AI 的僅是脫敏檔。
- 復原使用還原檔內代碼作精確字串比對，不再次執行 NER，也不猜測 AI 改寫過的代碼。使用單次替換避免原文被再次解讀為代碼。
- AI 回覆中的代碼可重複、重新排序或省略；只替換實際出現的代碼。未使用的映射正常保留；陌生或被 AI 改動的代碼保留並回報無法復原。
- 還原檔驗證版本、必要欄位、代碼結構、重複與衝突、數量及大小，拒絕不合法映射。不會把 AI 新生成的姓名誤稱為可還原內容。
- 復原下載格式跟隨 AI 回覆檔案的格式；貼上文字則下載 TXT。復原的是代碼代表的內容，不是把 AI 修改的整份文件回滾成原始文件。

## 原格式檔案處理與排版

每種格式以各自的適配器讀取可處理文字與位置，套用共用辨識／代碼替換服務後，將結果寫回來源容器。不能用抽取文字後重建整份文件的方式冒充保留排版。

- **DOCX**：在文件 XML 的段落、表格、頁首頁尾及可識別文字框中替換文字，支援跨 run 的姓名與代碼；保留段落、表格、圖片、樣式及其他套件內容。跨樣式文字的替換內容繼承起始 run 樣式。代碼比原文長時可能造成換行變動。
- **XLSX**：替換所有工作表的字串儲存格、共享字串及可處理的富文字；保留儲存格型別、樣式、公式、合併、列高、欄寬、圖片及其他套件內容。公式、嵌入物件及圖片內個資不在文字替換範圍，畫面與文件明列此界線。
- **PDF**：文字層辨識後，依原文字位置真正移除敏感文字，再加入可抽取的代碼文字；不能只畫色塊蓋住仍可抽取的原文。保持頁面尺寸、非敏感內容及位置，使用支援中文字的字型；必要時縮小代碼字級。若指定區域無法容納可讀代碼，明確報錯，不交付被截斷的代碼。復原讀取代碼及其位置，移除代碼後寫入原文；因字型、長度與 PDF 排版限制，只承諾盡量保留視覺排版，不承諾逐位元一致。
- **TXT**：保持換行與可支援的來源編碼，只替換指定文字範圍。
- **CSV**：辨識各欄位解碼後的文字，替換後正確處理引號與跳脫，保留分隔符號、換行、欄位結構及既有引號風格；必要時補上引號確保有效 CSV。
- **JSON**：以語法感知的字串 token 範圍處理鍵與字串值，保留縮排、順序與非字串值，寫入時正確跳脫。替換鍵產生碰撞時拒絕輸出。
- **XML**：處理文字節點與屬性值，保持 XML 結構、命名空間、空白與註解，正確處理實體跳脫及 CDATA，不啟用外部實體。

脫敏與復原共用相同的格式適配器，以確保代碼跨 DOCX run、PDF 文字片段等仍能識別。輸出須重新解析確認有效，PDF 另檢查目標原文已從相關文字層移除、代碼可完整抽取。若內容結構無法安全處理，回報具體原因。

一般文字預設 UTF-8（含 BOM），提供 Big5 編碼選項；來源為 Big5 而復原原文包含無法編碼的字元時，明確要求改用 UTF-8。掃描 PDF、圖片文字與嵌入物件的 OCR 不含在第一版；遇到無文字層的 PDF 拒絕處理並說明原因，混合圖片 PDF 顯示未處理圖片文字的提示。

## Web 流程

提供兩個清楚分開的功能頁籤：

1. **脫敏**：上傳檔案或貼上文字 → 選擇辨識類型 → 執行 → 檢視結果 → 下載同格式脫敏檔與 JSON 還原檔。頁面顯示送給 AI 時要保留完整代碼的提示。
2. **復原**：上傳 AI 回覆檔案或貼上文字 + 上傳還原檔 → 執行 → 檢視已復原代碼數與未識別代碼 → 下載同格式復原檔；貼上文字可查看及複製復原文字。

繁體中文介面顯示檔案格式及大小限制。空檔、不支援格式、損壞文件、無效還原檔、模型載入與設定錯誤均提供可理解的訊息。原始個資不會出現在脫敏檔與辨識報告下載中；原文只在使用者持有的還原檔及復原結果中出現。

模型延遲初始化並重複使用，避免每次請求載入。模型初始化與推論採鎖避免同時使用同一實例；長文字分段處理並保留全域位置，切片重疊區的辨識結果去重。復原流程不載入 CKIP。

## 結構與邊界

- app.py：保留命令列示範入口，改為使用共用服務。
- pii_service/：設定驗證、Recognizer 工廠、CKIP 包裝及分析／脫敏服務。
- file_adapters/：各格式文字定位、替換與原格式輸出。
- restoration.py：唯一代碼、還原檔驗證與單次復原。
- web.py、templates/、static/：Web 路由與介面。
- config/rules.yaml：預設規則及模型設定。
- requirements.txt、README.md：依賴、啟動方式、擴充規則範例與檔案支援界線。
- tests/：規則擴充、校驗、解析器與 Web 請求的驗證。

上傳預設限制 10 MiB，另外限制壓縮文件解開大小與處理文字長度；還原檔也有大小及項目數限制。伺服器使用記憶體或請求範圍的暫存檔，處理後清除，不永久保存原始上傳內容、映射及結果、不記錄原始個資。XML 禁止外部實體解析，頁面輸出做 HTML 跳脫。預設只綁定 127.0.0.1；此階段不加入帳號或多人權限系統。

## 驗證及驗收

1. 原本示範的身分證、手機及 CKIP 辨識行為仍可使用。
2. 在測試設定新增 EMAIL 規則，無需修改程式即可偵測與替換；停用規則後不再偵測。
3. 無效 regex、未知 validator、錯誤分數在設定載入時可定位原因。
4. 七種格式都有含中文及個資的樣本，驗證原格式可重新開啟、脫敏代碼與還原檔一致、復原後的語意內容正確；另外檢查未修改內容及關鍵樣式保持。
5. 驗證同名重用、不同人不同代碼、跨 run、重複／重排／省略代碼、未知代碼、映射衝突，以及 AI 回覆與來源格式不同的復原流程。
6. PDF 渲染脫敏與復原頁面檢查排版，另確認脫敏後不能抽取已移除的敏感文字，且代碼能完整抽取與復原。
7. 驗證無文字 PDF、損壞檔案、超量上傳、空內容、HTML 字串與 XML 外部實體的處理。
8. Web 脫敏、下載兩個檔案、上傳 AI 回覆及還原檔、下載復原結果的完整流程通過；多請求不互相讀取映射或結果。
9. CKIP 的單元測試用替身避免下載模型；另外使用本機模型完成一次真實姓名辨識驗證，若環境無模型則明確報告限制。

## 審閱重點

此版本已依使用者要求改為原格式下載及完整復原流程。排版盡量保留，但代碼長度、PDF 字型與 AI 自身改寫都可能使排版改變。第一版處理可讀取的文字內容，掃描圖與圖片 OCR 為後續擴充；不將未處理區域誤稱為已脫敏。
